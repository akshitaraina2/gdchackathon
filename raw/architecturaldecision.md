Decision 1 — Platform: Web app. Rationale: fastest to a previewable, shareable demo in one hour; no install friction for judges; runs on any device. Tradeoff: not the native mobile experience the real product would ship, but irrelevant for a preview.
Decision 2 — Triage logic: Use the Gemini API (via AI Studio / Antigravity) to interpret free-text symptoms and return a structured risk level + guidance. Rationale: handles messy natural-language input without us hand-coding rules; demos the "AI-powered" theme the event is about. Tradeoff: not clinically validated — explicitly framed as guidance, with a safety disclaimer always visible.
Decision 3 — Data: No persistence / in-memory only. Rationale: a preview doesn't need a database; skipping auth and storage saves the most build time. Tradeoff: nothing is saved between sessions — fine for a demo.
Decision 4 — Safety guardrail: The app must never present output as a diagnosis, must always show the disclaimer, and must default to a more cautious risk level when symptoms are ambiguous (err toward "see care," never away from it). Rationale: responsible health UX and it protects you in Q&A.
